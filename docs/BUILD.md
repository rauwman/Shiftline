# Building Shiftline

Shiftline is a SimHub plugin (settings pages, WPF) plus one LED script. The plugin stores your settings and publishes them to SimHub as properties `Shiftline.<Name>`; the script (`tools/Shiftline.plugin.js`) turns them into LED colours. The plugin carries the script inside its DLL and hands it to the loader LED profile, so a plugin update also updates the LEDs.

## Requirements

- SimHub (installed and started once)
- Visual Studio 2022 or newer with the workload ".NET desktop development" and the .NET Framework 4.8 targeting pack
- The environment variable `SIMHUB_INSTALL_PATH` points to your SimHub folder **with** a trailing backslash, for example `C:\Program Files (x86)\SimHub\`. Check with `echo %SIMHUB_INSTALL_PATH%` in a command prompt. If it is missing, set it and restart Visual Studio.

## Build and install

1. Clone the repository, for example to `C:\dev\Shiftline`. The project is `plugin\Shiftline\Shiftline.csproj`.
2. Close SimHub.
3. Open the project in Visual Studio.
4. **Debug** builds straight into the SimHub folder (needs write access there, so start Visual Studio as administrator if SimHub is under Program Files). **Release** builds to `plugin\Shiftline\bin\Release\Shiftline.Plugin.dll`, copy that file next to `SimHubWPF.exe` yourself.
5. Choose *Build > Rebuild Solution*, then start SimHub. Shiftline appears in the left menu. If SimHub asks whether to enable the new plugin, say yes and restart SimHub.

After you change the project file (new files), use *Reload Project* in Visual Studio before building.

## Import the LED profile

`profiles\Shiftline Loader.ledsprofile` is the only profile you need. It contains no LED logic: it runs the script that the plugin publishes. Import it once and a plugin update never needs a new import.

In SimHub open your LED device (for example *Arduino*), open the **Profiles manager**, choose *Import profile* and select the file. Select the profile and start at LED 1. It is built for up to 48 LEDs (2 x 8 on the sides + 32 on top); only as many as you set as layout in the plugin are used.

Without the plugin, or when the script does not compile, LED 1 and 2 blink red alternately.

## Test without a game

Open the plugin's **Settings** page and use the test mode: *Manual* lets you pick a scenario (for example "Yellow flag" or "Pit limiter in pit lane") with sliders for RPM and brake, *Auto* runs through all scenarios every 3 seconds. The sliders only apply to the scenario "RPM and brake (use the sliders)". Switch the test mode back to *Off* afterwards. SimHub's own test data editor does not reach this profile, which is why this mode exists.

## Tools

```
cd tools
python3 -I gen.py ../plugin/Shiftline                              # regenerates Settings.cs and TestScenarios.cs from the script
python3 -I check.py ../plugin/Shiftline gen_summary.json           # static checks (pip install tree-sitter tree-sitter-c-sharp)
node test_modes.js && node test_layout.js && node test_ui_values.js && node test_effects.js && node test_loader.js
python3 -I make_profile.py --loader loader.js "../profiles/Shiftline Loader.ledsprofile" "Shiftline Loader"   # only when loader.js changes
```

- `Settings.cs` and `TestScenarios.cs` are generated from the script. A new setting goes into `SL_DEFAULTS` in `tools/Shiftline.plugin.js` first, then `gen.py` creates the property, and it needs a control on a settings page (`check.py` fails when a setting has no control).
- The loader profile only changes when `tools/loader.js` changes, which should be rare.

## Where things are

| Path | Content |
|---|---|
| `plugin/Shiftline/` | The plugin. `Settings.cs`, `TestScenarios.cs` and `TabSettings.cs` are generated by `tools/gen.py` |
| `plugin/Shiftline/ShiftlineStyles.xaml` | The look: glass cards, tiles, switches, tabs, sliders, page background |
| `plugin/Shiftline/*Page.xaml` | The pages: Home, Dash Panel (LedPage), Presets, Theme Studio (ColoursPage), Settings |
| `plugin/Shiftline/PresetStore.cs`, `ProfileStore.cs` | Presets and settings profiles/backups (JSON files in `PluginsData\Shiftline`) |
| `plugin/Shiftline/UpdateService.cs` | Update check and installation through GitHub releases |
| `tools/` | The LED script, the generator, checks and mock tests |
| `installer/` | Inno Setup script for the installer |

Settings are stored in SimHub's plugin settings (`PluginsData\Common\Shiftline.GeneralSettings.json`) and survive updates.

## If the build fails

Copy the full error text into an issue. Common causes:

- `SIMHUB_INSTALL_PATH` is missing or has no trailing backslash: the SimHub references show a yellow warning icon
- A SimHub DLL from the reference list (`InputManagerCS`, `log4net`, `MahApps.Metro`) is missing in your SimHub version: remove that reference from the project
